# insurance-form — 보험설계사용 개인정보 입력 페이지

보험설계사가 자신의 기기에서 가입자에게 보여주고, 가입자의 개인정보를 단계형 폼으로 입력받아
**UTF-8 BOM CSV 평문 파일**로 기기 기본 다운로드 경로에 저장하는 순수 정적 프론트 페이지입니다.

## 구성

순수 정적 번들(빌드 불필요). GitHub Pages 공개 리포로 그대로 배포합니다.

| 파일 | 역할 |
|------|------|
| `index.html` | 마크업(PIN 게이트 / 3단계 폼 / 완료 화면 / 토스트) |
| `styles.css` | 디자인 토큰·컴포넌트(둥근 카드·블루·세그먼트/칩/토글)·애니메이션 |
| `app.js` | 상태·검증·단계전환·CSV 생성/다운로드·완료 UX (ES module) |
| `lib.js` | 순수 함수(검증·마스킹·CSV·BOM·파일명) — 단위 테스트 대상 |
| `config.js` | 고정 PIN, 이메일 도메인/관계 옵션, 동의 문구, 유휴 초기화 시간(기본 1시간) |
| `robots.txt` | 검색엔진 색인 차단(noindex) |
| `lib.test.mjs` | `lib.js` 단위 테스트 (`node --test`) |

## 사용 흐름

1. 설계사 기기에서 페이지를 연다(고정 PIN 입력 → 진입).
2. **Step1 인적사항** — 개인정보 수집·이용 동의 체크 후 이름·연락처(필수) 등 입력.
3. **Step2 신분·보험상세** — 주민등록번호(필수)·직업, 피보험자(가입자 동일 토글 시 본인 정보 자동입력·입력란 비활성), 수익자 최대 3명(추가/삭제), 납입계좌.
4. **Step3 확인·저장** — 요약 확인 후 저장 → 전체 데이터가 담긴 CSV 1개가 다운로드된다.
5. **완료 화면** — 파일명·CSV 미리보기표 확인, 다시 다운로드 / **PDF로 저장**(선택) / 처음부터 다시(연속 응대).

### 입력 편의

- **연락처**: 숫자만 입력, 3-4-4 자동 하이픈(최대 11자리).
- **주민등록번호**: 숫자만 입력, 13자리 상한, 6-7 자동 하이픈.
- **이메일**: 아이디 + 도메인 선택박스(네이버·Gmail·다음·한메일·카카오·네이트) + 직접 입력.
- **PDF 저장**(선택): 항목/값 2×n 표를 새 창에 렌더링 후 브라우저 인쇄(PDF로 저장)로 출력 — 외부 라이브러리 없이 한글을 안전하게 렌더링.
- **유휴 초기화**: 1시간(`config.js`의 `IDLE_RESET_MS`).

## 검증 규칙

- 필수: 이름, 연락처, 주민등록번호.
- 형식: 주민번호 `^\d{6}-?\d{7}$`, 전화 `^01[0-9]-?\d{3,4}-?\d{4}$`, 이메일(입력 시).
- 수익자는 이름 입력 시 관계 필수. 빈 선택값은 빈 CSV 컬럼으로 저장.

## CSV 사양

- 인코딩: UTF-8 + BOM(Excel 한글 호환).
- 컬럼 고정 순서(수익자 1~3 반복 컬럼 항상 존재), 1행 = 1가입자.
- 파일명: `이름_연락처뒤네자리_YYYYMMDD.csv`.
- 결제수단 컴럼은 제거됨(총 24컬럼).

## 테스트

```bash
node --test        # lib.js 순수 함수 단위 테스트(12건)
```

브라우저 e2e(수동): PIN 통과 → 3단계 입력 → 필수 미충족 차단 → 저장 → CSV 내용/파일명 확인 →
완료 화면 버튼 → 다운로드 실패 토스트. 대상: 최신 Chrome/Edge + 모바일 Safari, 저장 파일을 Excel에서 한글 정상 오픈 확인.

## 배포 (GitHub Pages)

1. 이 폴더를 새 GitHub 공개 리포에 push.
2. Settings → Pages → Branch `main` / root 로 배포.
3. 배포 URL을 설계사 기기에서 접속(고정 PIN은 `config.js`의 `APP_PIN`).

## ⚠️ 보안·개인정보 고지 (중요)

이 페이지는 **사용자(요청자)가 리스크를 인지·수용한 결정**에 따라 다음과 같이 동작합니다.

- 가입자 개인정보(주민등록번호·계좌 포함)를 **암호화·마스킹 없이 평문 CSV**로 다운로드 경로에 저장합니다.
  기기가 유출되면 그대로 노출되며, **개인정보보호법(PIPA) 위반 소지**가 있습니다.
- 공개 GitHub Pages + `config.js`의 **고정 PIN은 소스에 그대로 노출**되어 실제 보안이 아닙니다.
  우발적 접근 차단 수준이며 **대면 사용을 전제**로 합니다.

적용된 **저비용 완화책**(비차단): 검색 색인 차단(`robots.txt`), 화면 표시 마스킹(주민번호·계좌 뒷자리),
완료/유휴 시 폼·메모리 초기화(`config.js`의 `IDLE_RESET_MS`), 애널리틱스 없음, 저장은 사용자 버튼 클릭(제스처)에서만 실행.
운영 시 최소한 HTTPS(Pages 기본)와 대면 관리 절차를 병행하길 권장합니다.

## 잔여 확정 항목(합리적 기본값으로 진행됨)

- 개인정보 수집·이용 동의 정식 문안(`config.js`의 `CONSENT_TEXT`) — 법무 검토 후 교체.
- 이메일 도메인 목록(`config.js`의 `EMAIL_DOMAINS`) — 필요 시 추가/조정.
